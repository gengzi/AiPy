什么样的数据集能微调 Qwen3-Embedding-0.6B？
这类嵌入模型的微调目标是：让语义相近的文本在向量空间中距离更近，不相关的更远。因此，训练数据必须包含 文本对之间的语义关系。

✅ 适合微调的数据集类型：
| 类型                              | 说明                           | 示例数据集                                                   |
| --------------------------------- | ------------------------------ | ------------------------------------------------------------ |
| **1. 正样本对（Positive Pairs）** | 两个语义相似/相关的句子        | - 查询 & 相关文档（如 MS MARCO） - 同义句（如 Paraphrase 数据集） - 问答对（问题 & 答案） |
| **2. 三元组（Triplets）**         | `(anchor, positive, negative)` | - 一个问题 + 正确答案 + 错误答案 - 一个句子 + 同义句 + 无关句 |
| **3. 标签分类数据（间接使用）**   | 同一标签下的句子视为正样本     | - 情感分类（正面评论互为正样本） - 新闻分类（同主题新闻互为正样本） |

参考官方评估数据集

- **MTEB**（Massive Text Embedding Benchmark）
- **C-MTEB**（中文版 MTEB）

这些任务对应的数据集都**天然适合微调 embedding 模型**。

#### 数据集格式：

用什么 loss，就喂什么料；loss 决定格式，格式服务目标。
损失函数（loss function）”决定的。不同的损失函数，要求输入的数据结构不一样



#### 损失函数

损失函数 = **老师批改作业的标准**。

- 你让模型把两个句子变成向量。
- 模型输出两个向量。
- 损失函数说：“这两个向量应该很像（如果是相似句），或者很不像（如果是无关句）。”
- 如果不像，就扣分（loss 大）；如果像，就加分（loss 小）。
- 模型通过不断被“扣分”，学会怎么编码句子。

所以：**损失函数决定了“什么样的数据能用来教模型”**。



#### 常见的 embedding 损失函数 & 它们需要的数据格式

### 1️⃣ **`MultipleNegativesRankingLoss`（最常用）**
- **用途**：训练检索模型（比如问答、搜索）
- **它怎么教模型？**
  
  - 给它一组 `(问题, 正确答案)` 对。
  - 它自动把**同一个 batch 里其他问题的答案**当成“错误答案”（负样本）。
- **需要的数据格式**：
  
  ```python
  InputExample(texts=["问题", "正确答案"])
  ```
  ✅ 只需要两个句子！不需要标“0/1”，也不用写负样本！

> 💡 为什么？因为损失函数自己会从 batch 里“挖”负样本。

#### 👉 举个生活例子：
老师给你两道题：
- 题1：问“苹果是什么？” → 答“一种水果”
- 题2：问“汽车是什么？” → 答“一种交通工具”

老师心里想：
- “苹果”的问题，应该和“一种水果”靠近；
- 但“苹果”的问题，**不应该**和“一种交通工具”靠近（虽然是别人的答案，但拿来当反面教材）。

所以，**只要提供 (问, 对) 对，老师（损失函数）自己会找“错的答案”来对比**。

---

### 2️⃣ **`ContrastiveLoss`（对比损失）**
- **用途**：判断两个句子是否相似
- **它怎么教模型？**
  - 你必须明确告诉它：这对句子是“相似”（label=1）还是“不相似”（label=0）
- **需要的数据格式**：
  ```python
  InputExample(texts=["句子A", "句子B"], label=1.0)  # 相似
  InputExample(texts=["句子A", "句子C"], label=0.0)  # 不相似
  ```

> ❗ 必须提供 `label`！而且负样本要你自己准备。

#### 👉 例子：
- (“你好”, “您好”) → label=1（相似）
- (“你好”, “今天下雨了”) → label=0（不相似）

---

### 3️⃣ **`TripletLoss`（三元组损失）**
- **用途**：让 anchor 更靠近 positive，远离 negative
- **需要的数据格式**：
  ```python
  InputExample(texts=["锚点句", "正样本", "负样本"])
  ```
  比如：
  ```python
  InputExample(texts=["苹果是什么？", "一种水果", "会飞的动物"])
  ```

> ❗ 必须显式提供负样本，而且质量要高，否则学不好。

## 🔁 四、反过来理解：数据格式 → 决定了你能用什么损失函数

| 你的数据长这样           | 你能用的损失函数                                             |
| ------------------------ | ------------------------------------------------------------ |
| `[s1, s2]`，无 label     | ✅ `MultipleNegativesRankingLoss`<br>✅ `CosineSimilarityLoss`（如果 s1/s2 是语义对） |
| `[s1, s2]`，有 label=0/1 | ✅ `ContrastiveLoss`                                          |
| `[anchor, pos, neg]`     | ✅ `TripletLoss`                                              |
| 只有单个句子             | ❌ 不能直接训练 embedding 模型（除非用 SimCSE 等自监督方法）  |

## 🧠 五、为什么 Qwen3-Embedding 推荐用 `(query, doc)` 格式？

因为：
1. 它是为 **检索任务** 设计的（RAG、搜索等）；
2. `MultipleNegativesRankingLoss` 是目前**效果最好、最简单**的训练方式；
3. 不需要人工标注负样本，省时省力；
4. 支持 instruction，可以在 query 前加任务描述，提升泛化能力。

所以官方示例都用：
```python
["Instruct: ...\nQuery: xxx", "relevant passage"]
```

### 指令微调

- **发生阶段**：**模型训练阶段**

- **做法**：在训练时，把输入数据改成 `指令 + 任务内容` 的形式，让模型学会“根据指令调整行为”。

- **典型场景**：大语言模型（如 LLaMA-2-Chat、Qwen-Chat）的训练。

  ```
  输入: "将以下英文翻译成中文：Hello world"
  输出: "你好，世界"
  ```

- **目的**：让模型具备**遵循指令生成答案**的能力。

> 📌 **Qwen3-Embedding 确实在训练时用了大量带 instruction 的数据**，所以它**支持**理解 instruction。
>  但**你使用时加 instruction，并不是在做微调**，而是在**利用它已有的能力**。



如果你需要进行指令微调：

**用你的领域数据 + instruction 格式 微调 Qwen3-Embedding** → 这才叫 **指令微调**

### Qwen3 embeding

embedding 微调如果不冻结某些层，则是全参数微调 （包括所有 Transformer 层的权重）

| 微调方式                                 | 修改的参数                                    | 说明                                       |
| ---------------------------------------- | --------------------------------------------- | ------------------------------------------ |
| **全参数微调（Full Fine-tuning）**       | **全部参数**（包括所有 Transformer 层的权重） | 效果最好，但显存消耗大                     |
| **冻结部分层（Freeze Backbone）**        | 仅修改顶层（如 Pooling 层、MLP 头）           | 节省资源，适合小数据                       |
| **LoRA（用于 LLM，较少用于 embedding）** | 仅修改低秩适配矩阵                            | 主要用于大语言模型，embedding 模型一般不用 |

> 📌 **你当前用的 `Sentence Transformers` 默认是全参数微调**（除非你手动冻结某些层）。

一般的embedding 模型结构：

```
Input → [Tokenizer] → [Transformer Layers (12/24层)] → [Pooling] → Embedding
```

**Pooling 层**

**Pooling 层（池化层）** 在 embedding 模型（如 Sentence-BERT、Qwen-Embedding、BGE 等）中扮演着 **“从词向量生成句向量”** 的关键角色

**Pooling 层的作用是：把一个句子中每个 token（词/子词）的向量，合并成一个固定长度的句子级向量（sentence embedding）**

Transformer 模型（如 BERT、Qwen）在处理一个句子时，会为**每个 token 输出一个向量**。经过 tokenizer 分词后变成 n个 token，模型输出 **n 个 768 维（或更高维）的向量**，但我们要的是 **整个句子的一个向量表示**

 **Pooling 本身没有可训练参数**，它们只是数学操作（平均、取最大、取第一个，取最后一个）

## 常见的 Pooling 方法

### 1. **[CLS] Pooling（最常用之一）**

- 只取 `[CLS]` token 对应的向量作为整个句子的表示
- BERT 原始设计就建议用 `[CLS]` 做分类任务
- **优点**：简单高效
- **缺点**：在非分类任务（如语义相似度）中可能不如其他方法

### **Mean Pooling（平均池化，目前最主流）**

- 对所有 **非特殊 token**（去掉 `[CLS]`, `[PAD]` 等）的向量求**平均值**
- **优点**：
  - 保留了所有词的信息
  - 实验证明在语义相似度任务上效果通常优于 [CLS]

### **Max Pooling（最大池化）**

- 对每个维度取所有 token 向量中的**最大值**
- 能捕捉最显著的特征，但可能丢失语义完整性
- 很少单独使用，有时和 Mean Pooling 拼接（Mean + Max）

### **Weighted Pooling（加权池化）**

- 给不同 token 赋予不同权重（如 TF-IDF、注意力权重）
- 更高级，但需要额外计算

### **`lasttoken` Pooling**

* 池化策略：**取序列中最后一个有效 token 的向量作为整个句子的 embedding。** [EOS]

，**取 `[EOS]` 这个 token 对应的向量** 作为整个句子的 embedding（这就是 `lasttoken` pooling 的含义！）。

> 💡 为什么取 `[EOS]`？
>  因为在生成模型中，`[EOS]` 位置的 hidden state 已经“看过”前面所有词，是**对全文的总结**，很适合作为句子表示。





## 举个实际例子

输入句子：`"如何申请电子社保卡？"`

1. Tokenizer → `["[CLS]", "如", "何", "申", "请", "电", "子", "社", "保", "卡", "?", "[SEP]"]`
2. Transformer → 输出 12 个 1024 维向量（假设 Qwen 是 1024 维）
3. **Mean Pooling**：
   - 忽略 `[CLS]` 和 `[SEP]`（或根据配置决定是否包含）
   - 对中间 10 个词向量求平均 → 得到 1 个 1024 维的句子向量
4. 这个向量就可以用来：
   - 计算与另一个句子的余弦相似度
   - 存入向量数据库做检索

## 如何控制哪些参数被更新？（进阶）

### 1. **冻结主干，只训练顶层**

```
# 冻结 Transformer 所有参数
for param in model[0].parameters():
    param.requires_grad = False

# 只训练 Pooling 或额外 Dense 层（如果有）
```

### 2. **只训练最后几层**

```
# 冻结前 10 层，训练最后 2 层（以 12 层为例）
for layer in model[0].auto_model.encoder.layer[:10]:
    for param in layer.parameters():
        param.requires_grad = False
```

> 这在数据少、怕过拟合时很有用。

###  常用标记

人类读句子是连续的，但**计算机只能处理固定长度的数字数组**。

大模型针对用户输入内容，

- 通过 tokenizers 进行分词，比如： 比如 “电子社保卡” → “电”、“子”、“社保”、“卡”
- 每个词通过模型定义好的词表，会返回一个词表的id （token id） 比如 “100”、“300”、“33”、“5”  对应  “电”、“子”、“社保”、“卡” 这几个词
- 并且所有句子也都必须一样长，才能转为固定长度的向量进行计算

有的句子长，有的短。怎么办？**答案：靠这些特殊符号来“对齐”和“标记”！**

###  `[CLS]` —— **“分类开始”标记**

放在句子**最开头**，告诉模型：“我要对整个句子做判断！”

```
输入: "这部电影太棒了！"
变成: [CLS] 这 部 电影 太 棒 了 ！
```

- **用在哪**？
   BERT、RoBERTa 等 **encoder-only 模型** 做分类时，就用 `[CLS]` 位置的输出向量代表整个句子。

### `[EOS]` 或 `[SEP]` —— **“句子结束”标记**

- **`[EOS]`**：End Of Sentence（句子结束）→ 常用于 **生成模型**（如 Qwen、Llama）
- **`[SEP]`**：Separator（分隔符）→ 常用于 **BERT 类模型**，分隔两个句子

```
输入: "你好"
模型看到: 你 好 [EOS]
句子1: "猫喜欢吃鱼"
句子2: "狗喜欢啃骨头"
输入: [CLS] 猫 喜欢 吃 鱼 [SEP] 狗 喜欢 啃 骨头 [SEP]
```

### `[PAD]` —— **“填充”标记**

把短句子“补长”，让所有句子一样长

```
句子1: 今 天 天 气 好 [PAD] [PAD] [PAD] [PAD] [PAD]
句子2: 我 爱 吃 苹 果 香 香 的 很 好
```

### `[BOS]` —— **“句子开始”标记**（较少见）

- 有些模型（如 T5）用它表示开始，但 **Qwen、Llama 通常不用**，直接从第一个词开始。

### `[UNK]` —— **“不认识的词”**

- 如果遇到词表里没有的字/词（比如生僻字、新网络词），就用 `[UNK]` 代替。
- 输入 “绝绝子yyds”，如果 “yyds” 不在词表 → 变成 “绝 绝 子 [UNK]”

| 缩写         | 英文全称                  | 中文直译     | 实际作用（通俗解释）                                 |
| ------------ | ------------------------- | ------------ | ---------------------------------------------------- |
| **`[CLS]`**  | **Classification Token**  | 分类标记     | “整句话的代表”——放在句首，用于句子分类或匹配任务     |
| **`[SEP]`**  | **Separator Token**       | 分隔标记     | “这里是分界线”——用来分隔两个句子（如问答对）         |
| **`[PAD]`**  | **Padding Token**         | 填充标记     | “空白占位符”——把短句子补长，让所有句子一样长         |
| **`[UNK]`**  | **Unknown Token**         | 未知标记     | “我不认识这个词”——代替词表里没有的字或词             |
| **`[MASK]`** | **Mask Token**            | 掩码标记     | “这里被盖住了”——BERT 训练时随机遮盖词，让模型猜      |
| **`[BOS]`**  | **Beginning Of Sentence** | 句子开始标记 | “我要开始说话了”——有些模型用它表示句子开头（较少见） |
| **`[EOS]`**  | **End Of Sentence**       | 句子结束标记 | “我说完了”——告诉模型这句话到此结束，常用于生成模型   |

### 总结记忆口诀：

> **CLS 看整体，SEP 分两句，**
>  **PAD 来补齐，UNK 不认识，**
>  **MASK 要猜词，BOS 开始说，**
>  **EOS 说完啦！**





### Encoder 和 decoder 和 seq2seq

Encoder（编码器）—— “读懂输入”

把一段输入（如句子）**压缩成一个语义向量（或一组向量）**，代表它的含义。

```
输入："电子社保卡怎么办理？"
Encoder 输出：一个 768 维的向量 → 这个向量包含了“问题意图、关键词、语义”等信息
```

文本分类、问答匹配、embedding

Decoder（解码器）—— “生成输出”

根据一个“意思”（可以是向量、也可以是前面已生成的词），**一步步生成新的序列**（如句子）。

```
已知“用户想问社保卡”
Decoder 一步步生成："您" → "可以" → "登录" → "人社" → "APP" → "办理" → [EOS]
```

- **自回归（Autoregressive）**：每次只预测下一个词，基于之前生成的内容

- **不能看到未来**（只能看左边）

对话、写作、代码生成

* 现在大模型多用 Decoder-only（如 GPT、Qwen）
  1. **训练更简单**：只需“预测下一个词”，数据 everywhere（网页、书籍）
  2. **生成能力强**：天生为自回归生成设计
  3. **Scaling Law 效果好**：参数越大，效果越强

Seq2Seq（Sequence-to-Sequence）—— “先理解，再表达”

一种**架构模式**，由 **Encoder + Decoder** 组成，用于把一个序列**转换成另一个序列**。

```
中文句子	→	英文翻译
```

翻译、摘要、复杂生成





### Transformer 

在 2017 年提出的 **原始 Transformer** 是为**机器翻译**设计的

```
[ Encoder ] → (语义表示) → [ Decoder ]
```

但是演进后大模型，只需要**“根据前面的词，预测下一个词”** 模型只需要“看左边，猜右边”。**大模型选择 Decoder-only，是因为“预测下一个词”这个任务，只需要 Decoder 就够了，而且更简单、更强、更省钱！**

#### Self-Attention 自注意

**就是让模型自动学会：“在理解某个词时，该看哪些其他词”**。

分别定义了三个矩阵（q，k，v ）在未训练时，都采用随机初始化

定义三个矩阵的目的，是仿照人类如何关联信息的优雅建模

q  我看的这个词我想关注什么

k  其他词有什么属性（标签）

v 其他词本身的真实信息 



点积约等于 cos 余弦相似度，表示这两个向量方向越近，值就越大，可以当做 两个词 之间的相关性的得分

我想要一个苹果来吃 



针对 吃 这个词，我  苹果  相关程度更高。 所以  吃（q） 和每个词的  k 的点积计算后， 我  苹果 的得分就会高点，再根据每个词v，加权平均，计算出了  吃 这个词的 新权重
